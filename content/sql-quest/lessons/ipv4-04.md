## Contexto

Agora é hora de **entregar o plano** do chamado nº 5. O pedido do cliente foi:
**"queremos separar o administrativo do prédio 2"**. Você já sabe dividir a
rede 192.168.10.0/24 em duas metades com o /25. Falta decidir **qual metade
fica com cada setor** e quais endereços cada equipamento vai receber.

## O plano de endereçamento

Um **plano de endereçamento** é a tabela que o técnico entrega ao cliente
dizendo qual endereço cada parte da rede usa. Sem ele, dois PCs acabam com o
mesmo IP e a rede para de funcionar.

| SubLAN | Rede | Gateway | Hosts | Broadcast |
|---|---|---|---|---|
| Administrativo (prédio 1) | 192.168.10.0/25 | 192.168.10.1 | .1 até .126 | 192.168.10.127 |
| Visitantes (prédio 2) | 192.168.10.128/25 | 192.168.10.129 | .129 até .254 | 192.168.10.255 |

O **servidor** do escritório fica no administrativo, com o IP fixo
**192.168.10.10**.

## O que é o gateway

O **gateway padrão** (*default gateway*) é a "porta de saída" da sub-rede: é
o endereço do roteador naquela rede. Quando um PC quer falar com outra rede,
ele entrega a mensagem para o gateway. Por costume, o gateway usa o
**primeiro host** da sub-rede:

- no administrativo, o primeiro host é o **.1**;
- no prédio 2, a rede é o .128, então o primeiro host é o **.129**.

## As três regras do plano

1. O gateway fica no **primeiro host** de cada subLAN.
2. **Nenhum IP se repete**.
3. **Nunca** dar a um equipamento o endereço de rede nem o de broadcast.

## Por que separar ajuda o cliente

- **Segurança**: os visitantes ficam numa rede separada do administrativo.
- **Menos tráfego**: o broadcast de uma subLAN não chega na outra.

## E se testar agora no Packet Tracer?

Se você ligar um PC de cada subLAN no mesmo switch, o ping entre eles **vai
falhar**. Isso não é erro do plano: falta o **roteador**, que liga as duas
sub-redes. Ele entra no capítulo 17.
